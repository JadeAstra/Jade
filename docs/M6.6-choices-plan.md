# Plan: the 118 M6.6 choices

The "Choices to confirm" on [M6.6-gaps.html](M6.6-gaps.html) were each checked against the code as it
is now (2026-11-03, after G67), with small scripts where a fact needed running. Nothing has been
changed yet. This page says what each one is now, what I recommend, and an order.

## In short

The page has 120 sections, 118 of them waiting for your verdict (two are notes).

| | Sections |
|---|---|
| Confirm as built, nothing to do | 40 |
| Confirm, but the page's text is out of date (later work changed it) | 31 |
| Already decided elsewhere: record it | 4 (D162, 8.1a, 8.4g, D149) |
| Confirm with a small change (messages, a parameter, a doc line) | 19 |
| A bug found while checking: fix | 17 (14 fixes in step 2) |
| A change that reverses an earlier decision or adds a rule: your say | 5 alone, 3 more beside a fix or a text (7 questions in step 4) |
| Worth doing, not urgent | 4 |

The bugs matter most. Four give a wrong answer or damage memory without a word:

1. **A value type over 64 KB corrupts memory** (Size). The limit is promised but not enforced: a
   102,400-byte value's field 199 was written into field 71.
2. **Removing from a set or map in a `for` over it skips items** (8.2i). `for x in s { s.remove(x) }`
   over 100 items visits 51 and leaves 49.
3. **A change made through a lambda's item is lost in some functions** (D167).
   `pts.forEach { it.translate(1, 0) }` changes the list, but `pts.filter { it.translate(1, 0); true }`,
   `map.forEach { k, v -> v.translate() }` and `g(pts[0])` compile and the change is lost.
   `for (p in pts) p.translate()` is an error.
4. **An `Atomic` whose kind of value changes can be left holding a bad pointer** (8.7f), when two
   cores store at once, one by the lock-free path and one by the lock. Narrow, but it is memory.

### Step 3: small changes, in a few batches (S each)

- **Messages that point the way**, all costless:
  - Kotlin's `@Target`, `@Retention`, `@Repeatable`, `@MustBeDocumented`, `@OptIn` say to delete them, and `@Deprecated` says it comes at 1.0 (8.6i).
  - `x.className`, `.simpleName`, `.qualifiedName` and `.javaClass` point to `#` (8.6k).
  - `throws A, B` says to join them with `|` (8.5k).
  - `uppercaseChar` and `titlecase` point to `upper()` (8.1c).
  - Java's `Color.WHITE` and `Font.BOLD` point to the camelCase names (8.9k).
  - `Rect(30, 40)` says x and y come first (D180).
  - `val b : byte = n` names `n.toByte()` (8.9c).
- **The language:**
  - A `tail fun` that never calls itself is an error (8.4d).
  - A lambda may end with `x++` (today `forEach { n++ }` does not compile).
  - Annotations are allowed on static fields, which reflection now lists (8.6h).
- **The library:**
  - `AssertionError`, `InternalError` and `CancellationException` take a cause (8.5b).
  - `Fonts.load` declares `throws IOException` (8.8j, 8.8k).
  - Font text is typed `string | char`, and `xHeight(scale)` and `capHeight(scale)` are added (8.9g).
  - A bundle prints as `params(size = 18)` (8.9e).
  - `paintInto` loses its unused `given` (8.9h), and `renderToImage` takes one scale (8.9i).
  - Field, parameter and result Classes keep who asked (8.6d).
  - The socket timeout is chosen by a flag, not by comparing message text (8.8f).
- **The tests:** the stress settings (native results, GC, threads, copy-reads) go into `tests/run.ps1`, so the promise in D163 doesn't hang on a scratch script (D163).

### Step 5: worth doing, not urgent (M each)

- More of the standard library inline: string's and Range's lambda functions, `require` and `check`
  (two forms instead of a lambda that may be null), `runCatching`, `LockBox.useKey` (8.4i). Today each
  call makes a closure, `require(x > 0) { ... }` even when it passes.
- `assert(cond) { "message" }`, the message made only on failure (8.5d).
- A constant `Color(255, 128, 0)` checked when compiled and made once (8.9b). Today it is a static call,
  four checks and a build each time, and 300 is an error only when it runs.
- Grid: `bytes` becomes `toBytes()` (it copies everything), `Surface.upload` stops copying, a grid of
  objects with no fill is a compile error (8.9f).
- A self-call that is a loop on another receiver: an extension (`n.next.last()`) or a method no class
  overrides. A 200,000-node walk overflows today. Timing risk in the VM's loop, as G33 found (8.4c).
- Inference that falls back to the checker's unknown type (`flag ? t : 1`) gives `T | int` (8.3e).
- Bytes in a parallel section refuse reading another core's part, as lists do (8.7h).
- `Process.run(timeout)` (8.8h); `AutoCloseable.close` declaring `throws IOException`, only if `use`
  is checked against the real class (8.5i).

### Later (proposed for M6.7 or after)

- A lambda given as an interface: one object, not two (8.4b, speed work).
- Sharing packed lists and long strings with workers (8.7i).
- More pieces per core when items differ in cost (8.7g).
- Recursive types (8.3f).
- "In twice, line 3, copied in" for an error in an inline body (8.4h).
- A program reading its own stack trace (8.5b), with its own decision on cost.
- Enum entries as arguments settled when compiled, not as the program runs (8.3d).
- `__text` declared as an external object (8.8j).
- `int64` and `float64` in Bytes (8.1e).
- Decided for M6.7 (2026-11-04): `use { }` checked against each class's `close()`, and
  `AutoCloseable.close` declaring `throws IOException` (8.5i); tasks started in a scope,
  `taskScope { }`, throwing the first failure where the scope ends (after 8.7a).
